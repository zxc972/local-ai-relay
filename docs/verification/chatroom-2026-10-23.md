# Chatroom verification, 2026-10-23

Scope: the local working-tree chatroom interface, with named participants over
ordinary stdio MCP and CLI. No UI automation, model process or provider API was
used by these checks. This feature has not been published as a release.

Observed:

- Three independent MCP server/client processes joined one temporary room.
  A broadcast reached both other members; a directed reply reached only its
  addressee. The sender did not receive its own message.
- An empty wait stayed pending until a real message. Cancel and leave released
  waits, and cancellation did not consume later messages.
- Twelve chatroom tests passed, including duplicate sends, ordered batches,
  explicit cursor replay, connection identity, EOF and nickname recovery.
- Full Python regression before the final status/shutdown refinements:
  85 tests, 80 passed, 5 packaging checks skipped in system Python. The final
  chatroom suite was then rerun: 12 passed.
- The five packaging checks were rerun with the bundled Python environment:
  all passed. They build and install a wheel outside the checkout, remove the
  staged source, and verify installed CLI chat exchange and MCP tool listing.
- Eight existing Pi extension contract tests passed. `git diff --check` passed.
- The real `work` chatroom was created with no members and no chat messages.
  Existing sender/receiver mailbox records were not imported or consumed.
- The previously prepared Accessibility bridge, its CLI flags and generated
  executable were removed. No Accessibility operation was performed.

Limits:

- These are protocol/process tests, not real Claude desktop or Claude CLI
  model conversations. Long-lived tool behavior in those hosts is unverified.
- Joined and listening are separate states. A host that cancels a request or
  ends a turn is not made receptive by registration alone.
- CLI and MCP are the delivered interfaces; there is no new desktop app
  installer or network service in this change.

## Persistent progress and recovery

The receiver now saves confirmed progress per nickname. A return to the same
room resumes that progress rather than skipping to the current end. Delivery
is recorded before a tool result is emitted; a batch left unconfirmed on
reconnect requires review and is not automatically dispatched again. Explicit
history replay is read-only and never advances progress.

Waiting status distinguishes actual waits from idle membership, unconfirmed
delivery, interruption and departure. POSIX uses a read-only process liveness
check plus the existing heartbeat. Other platforms retain heartbeat-based
freshness and do not use POSIX signal semantics.

Final Python regression on macOS with the bundled packaging-capable runtime:
**94 tests passed in 24.568 seconds; no skips.** This includes all 20 chatroom
tests and the five fresh-install/package tests. `git diff --check` passed.

The relay prevents automatic replay on ambiguous recovery; it cannot guarantee
exactly-once execution of actions in external applications. Old server/waiter
processes must be restarted to load the new progress code.
## 后台收件改造（2026-10-23）

用户要求空闲时不调用模型，有消息才唤醒当前 Agent。新版默认流程已经移除前台 wait 循环：join 接入后台，receive 每次取一条，回复原子确认，不需回复则 ack。

- 最终完整自动回归 107 项全部通过（31.235 秒），没有跳过测试。首次沙箱运行时旧 HTTP 测试不能绑定本机端口；最终运行允许测试绑定 127.0.0.1 临时端口。
- 其中 32 项聊天室测试包含 12 项新后台测试，覆盖空闲零回调、单消息单次唤醒、逐条回复与确认、定向隔离、退出停止、异常不重试、Claude 式后台任务完成与重新挂起、通知后未收件的重连恢复，以及共享 MCP 不误用另一聊天 ID。
- 独立 wheel 安装测试验证新后台模块已打包，离开源码目录也能启动后台进程、收件、回复确认并停止。
- 真实 work 数据库已通过 SQLite backup 备份至私有 .relay/backups/，保留原记录与进度。
- 当前 Codex 已以新后台方式加入 work，宿主发现确认原聊天支持外部输入，进程 89036 报告 waiting，next_tool/next_command 均为 null。旧 sender/receiver 后台仍保持关闭。
- 上述 running/发现成功尚不等于新消息已由 Agent 收到。另行安排一条本地测试脚本发送的消息验证回合结束后的真实唤醒；结果记录在私有 .relay/verification/，不得将测试脚本称为 Claude。

Claude Code 桌面和 CLI 的同一路径使用原生后台 Bash 完成通知。自动测试已验证本地等待命令的行为；真实 Claude 客户端端到端收发仍需实测。普通 Claude Chat 只有 MCP 时没有已接通的唤醒入口。当前改动仍是本地源码，未发布新版本。
