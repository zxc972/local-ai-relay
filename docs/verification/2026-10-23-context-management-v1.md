# 上下文管理首版验证

日期：2026-10-23。本地源码实现并加载到 `http://127.0.0.1:8787/`，未发布安装包。操作说明见 [上下文管理](../context-management.md)。

## 已实现

- 显式 v2 接入，旧调用继续 v1；旧监听运行或存在待确认消息时拒绝直接升级，避免混用回执。
- 通知扫描与处理回执分开。人类群发通知 Agent；v2 Agent 的普通人类回答仅保留在公共记录；定向消息、回复 Agent、显式讨论参与者仍可通知。
- 约 1 秒固定合并窗口、最多 16 条且受预算限制的批次、不可变批次 ID、逐消息确认；后到消息不能混入旧批次。
- 精简重复规则；按预算恢复历史、长消息连续分页；未完整领取时拒绝确认，不把字节上界描述成实际 token。
- 成员本机检查点，结构化发言者、状态与来源，版本比较及原子事务，保留两版。摘要写入和读取均不确认任务。
- 私聊按稳定身份过滤；新所有者不能凭同名接管旧私聊、检查点或 v2 回执。旧进程写入使用数据库触发器补齐身份。
- 网络检查点正文不发给服务器；提示信息故障不覆盖已经成功的发送/回执结果。
- 新邀请采用 v2。管理页面刷新可登记已有的人类成员，使用管理凭据及该成员凭据校验，不增加席位、不重新加入已离开的成员。

最终全量结果：**149 项，142 项通过，7 项跳过，0 失败**，耗时 56.562 秒。7 项跳过来自安装包测试：当前 Python 3.12 缺少 `setuptools` 和 `wheel`，因此没有验证构建和安装后的分发包。修改的 Python 模块编译、JavaScript 语法与空白检查通过。

新增场景包括：

| 场景 | 验证结果 |
| --- | --- |
| 1 个人类、7 个独立 Agent | 提问有 7 份待通知；7 条回答不产生面向其他 Agent 的 42 份待通知；显式讨论仍通知指定成员 |
| 批次部分处理、处理中到达新请求 | 精确确认指定 ID；非法混入后来消息会整体拒绝；下一批仍可及时唤醒 |
| 同一幂等键重试 | 不重复保存，升级或目标离开后重试仍保留原消息；改变显式通知对象拒绝 |
| 超长中文和 emoji 消息 | 连续分页后能重建全文；跳到末页不能越过未读部分，未完整领取不能 ACK |
| 10,000 条房间原文 | 恢复包不超过配置的序列化字节预算；可按消息 ID 查回最早原文 |
| 独立观点、身份和私聊 | 检查点可保留不同判断；旁观者及同名新身份不能查询私聊或原批次 |
| 检查点冲突、写入失败 | 旧版本可恢复，待办和回执不被摘要推进；普通提示失败不隐藏已确认结果 |
| 真实 HTTP、独立 MCP/CLI 进程 | 新工具参数、批次、检查点和恢复通过完整协议往返 |
| 模拟 Codex 常驻回调、Claude 原生后台命令 | 无消息时没有宿主回调；有消息合批通知，部分处理不提前重挂任务，整批完成后继续监听 |
| 管理页面的人类登记 | 普通邀请无法自报人类；登记保留稳定身份；成员退出后登记拒绝，不重新加入 |

宿主进程由本地测试替身模拟，没有在这些测试中调用真实 Codex/Claude 模型。这里的“无消息没有回调”是短时自动验证，不是实际 10 分钟桌面会话测量。
