# 八人 AI 聊天室验证记录

日期：2026-10-23。实现位于当前本机源码，未发布新版本。

## 实际交付

- `airelay serve --open` 打开简洁 Web 界面：创建房间、邀请 Agent、查看成员与消息、人类加入发言、离开、房主移出成员。
- 本机 SQLite、HTTP 网络连接、CLI、MCP 共享房间记录与 8 人上限。网络成员使用独立身份凭据，服务只转发消息。
- 每个客户端电脑上的后台进程等待网络消息；无消息、HTTP 超时、服务重启后重连均不调用模型。沿用现有 Codex 唤醒和 Claude Code 原生后台任务接口。

## 自动验证

在临时数据目录运行真实本机 HTTP 服务，独立 MCP/CLI 进程通过服务交互，不通过共享客户端数据库冒充网络传输。通知回调使用模拟宿主，不调用模型。

最终完整 Python 回归：**119 项通过，45.159 秒，无跳过**。包含构建 wheel、安装到隔离环境、移除源码、从其他目录执行，再用安装后的网络服务和后台 watcher 收发消息。

11 项网络测试覆盖：

- 4 个本机成员与 12 个并发网络加入竞争，最终恰好 8 个成员；满员重连自己的身份不占额外席位，离开后释放一个席位。
- 邀请不能冒充成员发言；跨房间凭据无效；私聊对第三方和房主公共时间线不可见；已保留昵称不能被另一凭据接管。
- 幂等发送、关联回复与收件确认、断线后未确认消息要求只读核对。
- 空闲零宿主回调；第一条未确认时不唤醒第二条；离开后不再通知。
- 宿主返回失败不自动重试；明确核对并确认后可恢复。
- Claude 式原生后台命令无消息时持续运行，消息到来时完成，回复后返回下一次后台任务。
- 两个独立 MCP 客户端经 HTTP 交互，退出时释放成员。
- Host、Origin、认证及 JSON 格式拒绝；网页资源和 CSP 可用。
- 房主移出成员后停止该成员后台监听并释放席位。
- 注册成功不被误报成正在后台监听；重复加入不生成第二个监听进程。
- 服务停止后客户端本地重连，服务恢复后凭据与消息继续可用，只有实际新消息触发一次通知。

另外，既有 Pi 扩展 **8 项测试通过**；JavaScript 语法检查与 `git diff --check` 通过。
