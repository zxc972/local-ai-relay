# 会话绑定与三组并发隔离验证

日期：2026-10-28。范围：`local-ai-relay_local` 开发副本。

## 改动

新增固定 `session_id` / `--session-id`，新邀请要求每个原生聊天使用自己的标识。共享 MCP 连接按会话路由；网络成员凭据增加会话维度；本地成员保存绑定。收发、历史、检查点、精确 ACK、后台通知和重挂命令使用同一身份。原生 `thread_id` 与绑定不一致时，在启动监听前拒绝。

绑定成员不允许漏带标识的 CLI/MCP 调用接管；换昵称或占用另一会话昵称被拒绝。绑定会话在 MCP 传输断开后保留，使用原标识重连，显式 leave 才退出。同一连接、同一房间不能混用旧版和绑定接入，避免新加入改变旧成员路由。

## 并发测试

`tests/test_chat_sessions.py` 使用临时目录、临时 SQLite、系统分配的 HTTP 端口。六个模拟 Agent 故意共用一个 `ChatEndpoint`（MCP 工具处理器）和客户端数据目录，以覆盖“多个聊天共用 MCP 连接/缓存”的情况。三个线程同步启动，每组每轮互发并精确确认，两侧各保存自己的摘要；共 10 轮。

| 场景 | 分组 | 常规消息 | 额外待确认消息 | 个人检查点 | 结果 |
| --- | --- | ---: | ---: | ---: | --- |
| 本地文件接入 | 同房间三组私聊 | 60 | 3 | 60 | 通过 |
| 本地文件接入 | 三个独立房间，重复 guide/worker 昵称 | 60 | 3 | 60 | 通过 |
| 真实 HTTP 接入 | 同房间三组私聊 | 60 | 3 | 60 | 通过 |
| 真实 HTTP 接入 | 三个独立房间，重复 guide/worker 昵称 | 60 | 3 | 60 | 通过 |
| 合计 | 每种场景 6 个模拟成员 | **240** | **12** | **240** | **通过** |

断言覆盖：

- 每次领取的消息 ID 必须与本组发送结果完全一致，不能混入其他组。
- 分页读取全部原文，并与本组消息 ID 集合完全比对；HTTP history 也逐成员核对。
- 每位成员只恢复自己的检查点正文，版本为 10，队列最终为空。
- 各组故意复用相同幂等 key，仍产生 60 个独立消息 ID。
- 48 次跨组读取原文/引用检查点来源、12 次跨组 ACK，合计 **60 次全部拒绝**；合法收件者的待确认状态未改变。

另外检查：漏带/未知会话标识、抢占昵称、CLI 越界读取及退出、唤醒目标不符、同名凭据缓存分离、离开后新会话不继承旧私聊/摘要、旧版接入兼容、MCP 重连。后台验证包括本地一次实际通知和 HTTP 返回的真实 CLI `watch` 命令，确认通知与后续重挂命令携带原标识；未调用真实模型或宿主 Agent。

## 在线服务与边界

本次没有重启服务、迁移现用数据、操作现有成员或给真实 Agent 发测试消息。前后监听 PID 均为：8787 → 62911，8789 → 64103。现有 MCP 进程和成员没有热升级；新代码在之后加载的客户端中使用，新邀请要求携带绑定。未绑定旧接入保留并明确标记 `legacy_unbound`，不宣称已有严格会话隔离。

会话标识是客户端提供的路由标识，不是原生宿主对调用来源的认证。复制另一聊天的标识、恶意本机进程直接读数据库、通用唤醒回调内部投错会话不在此检查的防护能力内。真实 Codex、Claude 等宿主的端到端连续聊天本次未测试。公开群发仍是同房间公共内容；各组要完全隔离，须使用不同房间。中间件不会拆分同一原生聊天自己的模型上下文。
