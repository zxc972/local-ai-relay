# AirRelay 房间管理与通用邀请验证

日期：2026-10-28。只修改本地开发副本，不重启在线服务，不操作真实房间或原生 Agent。

## 交付

- 页面名称、导航、文件打开提示与 SVG 图标统一为 AirRelay，移除“本地开发版”文案。
- 房间菜单支持关闭、重新打开、删除、恢复。删除为可恢复删除，记录仍在本机；恢复先回到关闭状态。
- 关闭或删除阻止后续加入、收发和确认，停止后台等待，并使旧监听代次失效；不杀死原生 Agent 进程，不确认或重做未完成任务。恢复、重新打开不自动启动旧监听。
- 管理操作仅供用户管理会话调用，普通 Agent 成员和邀请码不能调用。房间独立，关闭一个房间不改变其他房间。
- 邀请不包含 Python、源码或数据目录的个人绝对路径。提供项目目录内的 macOS/Linux 与 Windows PowerShell 命令，实际服务地址由当前部署生成。后台继续自动保存会话身份。

## 验证证据

`tests/test_room_lifecycle.py`：

- 任务 A 已领取、B 在队列，关闭时拒绝继续收件和确认；重新打开仍返回 needs_review，核对并确认 A 后才收到 B。
- 删除后正常列表不出现该房间，旧 Agent 接口返回已删除；恢复后保持关闭，重新打开后原身份和消息不丢失。
- 关闭、删除使真实 HTTP 后台等待线程退出；本地监听的旧代次在重新打开后也不能继续运行。
- 模拟用户、指导成员、执行成员，通过真实 HTTP、后台子进程和 CLI 完成三轮“用户 → 指导 → 执行 → 指导 → 用户”。执行成员实际写入临时文件，每个任务一次；共 9 次模拟宿主回调，空闲未新增调用。

`tests/test_local_no_keys.py`：源码打包解压到另一个含中文与空格的目录，使用相对入口 local_dev.py 实际加入、退出临时房间，客户端状态只写入新目录。

`tests/test_chat_ui.mjs`：确认前不执行关闭；切换房间后确认仍作用于原目标；关闭后不可发言；删除/恢复列表正确；不同部署地址的邀请均无个人路径，原服务返回的 CLI 绝对路径不会进入提示词。
