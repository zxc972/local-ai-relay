# AirRelay 连续三项任务的 token 前后对比

日期：2026-11-04。三组各使用一个独立 Codex 会话；两个聊天室组均只加入一次，连续处理三项任务。

本轮修改后总量为 **420,017 token**，比修改前 **429,116 token** 减少 **9,099 token（2.12%）**。直接执行相同任务为 **265,735 token**；聊天室与直接执行的倍率从 **1.61** 降到 **1.58**。

这是每组一条三任务序列，包含缓存输入。模型会自行选择读文件和调用工具的路径，本次结果是一次实测差额，不能把全部差额归因于提示词，也不能当成固定节省率或费用降幅。

| 流程 | 输入 | 其中缓存输入 | 未缓存输入 | 输出 | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 直接执行，同一会话 | 262,960 | 255,616 | 7,344 | 2,775 | **265,735** |
| AirRelay 修改前，加入一次 | 424,392 | 400,896 | 23,496 | 4,724 | **429,116** |
| AirRelay 修改后，加入一次 | 414,409 | 391,680 | 22,729 | 5,608 | **420,017** |

总量 = 输入 + 输出；缓存输入已经包含在输入中，推理输出已经包含在输出中。新版本未缓存输入减少 767，输出增加 884。没有测账单或订阅额度。

| --- | ---: | ---: | ---: | ---: |
| 加入并待命 | — | 31,716 | 31,555 | 161 |
| 任务 1：付款金额 | 79,622 | 128,834 | 110,614 | 18,220 |

两个聊天室组各有 3 段 15 秒无消息等待，共 90 秒，新增模型回合与 token 均为 **0**。模型只在接入和每次任务通知后运行。任务间不是新建会话，也没有模型轮询。

## 改了什么

- 精简指导者与执行者角色、会话绑定和接入说明，保留整体目标、验收、授权范围、有限轮数和异常处理。
- 明确通常只需收件一次、完成验证后回复一次：`reply_to + delivery_id` 回复同时确认原消息，不再额外 ACK；无需回答才精确 ACK。日常不重复加入、拉取历史或查状态，异常/压缩后按需恢复。
- CLI 被工具捕获时使用紧凑 JSON，交互终端继续缩进；MCP 文本结果也使用紧凑 JSON，`structuredContent` 和所有协议字段保留。没有变更数据库、会话绑定或投递语义。

固定相同接入参数下，完整执行者邀请从 1,437 字 / 3,017 UTF-8 字节降到 1,143 字 / 2,065 字节；角色本身从 476 字降到 194 字。指导者完整邀请从 1,562 字 / 3,378 字节降到 1,180 字 / 2,180 字节。完整规则从 1,236 字节降到 1,032 字节。

对同一个实际旧版 join 返回包，仅压缩 JSON 空白，体积由 2,473 降到 2,302 字节，解析后的字段和值完全一致。这些是字符/字节测量，与上表真实 token 用量分别统计。

## 如何测量

- 实际 Codex CLI `0.166.0-alpha.5.1`，三组会话均核验为 `gpt-6.1-terra`、`max`，相同 `workspace-write` 权限。三组统一关闭 apps、plugins、remote_plugin，忽略用户配置；没有修改用户全局设置。
- 顺序为直接 → 旧版聊天室 → 新版聊天室。未固定模型随机性或控制跨会话缓存预热，也没有多轮独立重复。本轮设置与先前单任务实验不同，不能拿先前数字计算本次优化幅度。
- 三项任务逐步完善同一 `invoice.py`：仅累计已付款金额并校验；按客户分组；按顺序提取去重的未付款 ID。每项新增 7 项冻结测试，最终保留 21 项，不允许修改测试。
- 旧版和新版使用分别冻结的源码；同一基准控制器、任务和客户端设置。接入输入使用各版真实 Executor 角色，加相同的 CLI 加入说明；不是完整网页邀请发现或真实模型 MCP 接入测试。
- 使用独立临时目录、随机 HTTP 端口、真实 SQLite、监听回调和真实模型。派单由测试程序模拟；command 事件适配器通知宿主续接原 CLI 会话，Agent 自行收件、改代码、验证和发回房间。
- 使用 `turn.completed.usage`；本版 CLI 在 resume 后返回累计值，因此各阶段减去前一阶段累计值一次。已与这三个受测会话的 `token_count` 逐一核对，并确认模型、推理强度和写权限。
- 工具往返后的模型请求数：直接组 15 次；旧版 21 次；新版 20 次。旧版第一次发送前查过一次 `send --help`，新版没有；两组也存在其他读文件差异，实际发生的用量全部计入。
- 不包含指导模型、开发本基准的主聊天、或回归工具输出。本轮受测会话用量共 **1,114,868 token**。

## 验收与运行边界

三组共 9 项任务均通过独立验证，逐项为 7 / 14 / 21 项测试；原测试文本保持不变。两个聊天室组都复用同一个 session、一个成员绑定，分别恰好加入 1 次、收件 3 次、回传 3 次；6 条消息都各有一条关联回复和已确认回执，没有额外 ACK 或重复执行。

272 项 Python 回归和 43 项 JavaScript 测试全部通过，包含文本与结构化 MCP 结果一致性、CLI 中文/转义/分页字段语义保留及已有投递、隐私隔离、分页、恢复检查。

本轮未重启、迁移或操作现用 8789 房间；结束后检查同一服务 PID 与健康端点，临时测试服务和监听进程已退出。现有原生 Agent 对话的角色提示词不会被这次源码修改自动替换。

本次验证的是 macOS 下真实 CLI 加通用 command 回调；没有测试桌面原生 IPC 自动唤醒、Windows 基准运行、长项目上下文压缩效果或任意客户端。空闲等待无需模型的结论只适用于本次验证的后台路径。
